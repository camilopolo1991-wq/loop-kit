# ADR-005: the install writes no settings file and fills three tokens

## Context

`install.sh` copies the kit into a home. A settings file belongs to the user and can hold approved commands and secrets, and the install runs once on a machine it cannot see. So the install must be small, refuse to overwrite, and leave the user's own files alone.

## Decision

`install.sh` never edits `settings.json` or `CLAUDE.md`, never pushes, and does not touch git. In the copied files it fills three tokens and nothing else:

- `@LOOP_PYTHON@` with the interpreter given to the install.
- `$HOME` on the hook command lines of the installed agent files, with the literal home.
- `OWNER_HANDLE` with the value of `LOOP_OWNER` when it is set. Otherwise it stays and the install says in one line that it is set by hand.

It writes `config.env` last, through a temporary file renamed into place as the final step. It exits 4 when any destination file already exists. The owner registers the session hook in `settings.json` by hand.

## Deliberately not

- Not an edit of `settings.json`, in any form. `bin/loop-settings-merge` exists as a separate tool the owner runs, and the install does not call it.
- Not an overwrite of an installed file. Upgrade is its own mode, with a backup folder that must be empty.
- Not a fourth fill, and not a hook registered for the user.

## Consequences

- A new install leaves a short list of steps for the owner: put `bin` on `PATH`, make the record repository, register the hook, write the names list.
- A half-finished install has no `config.env`, so it is never mistaken for a finished one.
