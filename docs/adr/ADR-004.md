# ADR-004: the record is append-only and is corrected by new lines

## Context

The journal is the only history of a goal. A history that can be edited cannot be audited. `bin/loop-journal` appends one line per step with a UTC timestamp it measures itself, so no role types a time. The state file, `STATE.md`, holds current facts only and is edited in place; history belongs in the journal.

## Decision

The journal is append-only. A wrong line is corrected by a new line that says what it corrects, never by an edit or a deletion. The same holds for audit rows, exports and reports. `loop-journal` is the only way a role touches the journal, and its read forms (`--read`, `--dispatches`, `--check`) append nothing.

## Deliberately not

- Not an edit, a rewrite or a deletion of a journal line, even a mistaken one.
- Not a timestamp typed by a role.
- Not a history kept in `STATE.md`. Over 150 lines means something moves to the journal or a skill.
- Not a goal closed while `loop-journal --check` exits non-zero.

## Consequences

- A mistake stays visible next to its correction, so the auditor can see both.
- A writer's PASS needs a ROLLBACK line before it, and the ROLLBACK line names a file in the goal's evidence folder, not the surface it protects.
- The step log rewrites a home path to `~` on append, so the journal does not hold a user folder.

## Verification

```
bin/loop-journal --check <GOAL-ID>
```

Expected: exit 0 with the counts printed, and exit 1 when a writer task has a PASS or DONE line with no earlier ROLLBACK line. The command only reads.
