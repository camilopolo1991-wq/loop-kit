# ADR-003: the scan before every commit and every push, with a control that must fire

## Context

A zero from a scan means nothing if the scan could not have fired. `bin/loop-scan` first runs its detector on a built-in control, built to fire in every category. If the control does not fire, the scan is broken and it exits 3. It then scans, prints counts per category and file:line locations only, never the matched text, and exits 1 on any hit. A line that holds the token `loop-scan:control` is a deliberate test string, skipped, and the count of skipped lines is printed.

## Decision

- Before every commit: `loop-scan` on the staged diff, or on the files to be committed. A hit stops the commit.
- Before every push: `loop-scan --range origin/<RECORD_BRANCH>..HEAD`. A hit stops the push.
- The scan output is kept with its control line, so a clean result can be told from a broken scanner.

## Deliberately not

- Not a scan whose control is not printed, or a clean result quoted without it.
- Not a commit that proceeds on a scan that exited 3.
- Not the matched text in any output. A scan prints locations and counts.
- Not `loop-scan` with no file argument for the writer. The writer's git hook denies it, because it would shell out to git.

## Consequences

- Every commit and push carries two saved scan outputs, each with `control=fired`.
- Bare UUIDs and sha256 digests are not hits, because they were noise in every earlier scan.
- A redactor tag inside a path is a hit under its own category, tag.

## Verification

```
bin/loop-scan docs/adr/ADR-003.md
```

Expected: exit 0, the control reported as fired, and zero hits. A run in which the control does not fire is a failure whatever its hit count. `tests/rows/K05-C8/run.py` holds the rows for the tag category and the skipped control line.
