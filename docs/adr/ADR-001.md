# ADR-001: every shell command runs through the guard runner

## Context

An agent with a shell will sooner or later print a secret or a name. A prompt that says "do not" does not stop it. `bin/loop-guard-run` runs one command with stdin closed and passes its merged output through the redactor line by line. `hooks/pretool-guard.py` requires the command to be exactly one such heredoc: the opener, the body, the terminator line and nothing after it. Text after the terminator ran outside the redactor until the review finding B42 of 2026-10-20, and the hook now rejects it.

## Decision

Every shell command in the loop is one `loop-guard-run` heredoc. The session-wide hook denies any other form, and its default mode is `require`.

## Deliberately not

- Not a bare command, and not a command followed by anything after the terminator.
- Not the `wrap` mode as the default. It rewrites a command into the guarded form and is for use only after it is proved on the Claude Code build in use.
- Not a fallback to a `python3` or `python` found on `PATH`. When `LOOP_PY` does not run, the runner exits 3 and says so.

## Consequences

- Output is masked before a role reads it, so the redactor can also mask an ordinary word. The answer is to reword, never to switch it off.
- The redactor is a net. It is not permission to print what it would mask.
- A denied bare command is not a finding: the hook names the heredoc form, and the next command uses it.

## Verification

```
tests/rows/C1/run.py <tree> <home> <work>
```

The rows feed the writer's shell hook one hook JSON each, in the guarded heredoc shape, and judge deny against allow. Every row prints PASS or FAIL, and the run ends with a count.
